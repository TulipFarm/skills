# Hiring

Open a role with a clear bar before you talk to anyone, so screening is consistent and
defensible instead of vibes. This is hiring guidance, not HR or legal advice.

## When to use

Use this skill when opening a new role, rewriting a stale job description, or setting up
how candidates move through a pipeline. Stop at the offer of an interview — the questions,
scorecard, and evaluation kit live in `interview-prep`.

## How to run a hire

1. **Define the role before the ad.** Write the one outcome this hire owns in twelve
   months and the three to five things they will actually do week to week.
   - If you cannot name the outcome, you are not ready to post.
   - Pin the level, reporting line, and whether it is replacement or net-new.
2. **Split criteria into must-have and nice-to-have.** Must-haves are disqualifying if
   absent; everything else is a nice-to-have. Keep must-haves to five or fewer.
   - State each as an observable signal ("has shipped X"), not a proxy ("rockstar").
   - Drop unjustified degree, years, or pedigree gates — they shrink the pool and
     smuggle in bias. Justify any that stay.
3. **Write the job description to attract, not filter.** Lead with the mission and impact,
   then responsibilities, then must-haves as a short honest list.
   - Use plain, gender-neutral language; cut jargon and inflated requirement counts.
   - State range, location/remote policy, and what the first project looks like.
4. **Build the screening rubric from the must-haves.** One row per criterion, a 1–3
   anchor for each, and a hard yes/no gate on the disqualifying ones.
   - Score every applicant on the same rubric; record evidence, not impressions.
   - Calibrate on the first handful before scaling.
5. **Structure the pipeline as named stages with a purpose each.** Apply → screen →
   first interview → onsite/loop → decision. Each stage tests something the prior
   one could not, and the bar to advance is written down.

## Output format

```
Role: <title> · Level: <L> · Reports to: <manager>
12-month outcome: <one sentence>
Must-have (gate): 1) … 2) … 3) …
Nice-to-have: …
JD: mission · responsibilities · requirements · range/location
Screening rubric: criterion | 1–3 anchors | gate y/n
Pipeline: apply → screen → interview(s) → decision  (advance bar per stage)
```

Keep the rubric and pipeline in one doc so everyone screens against the same bar.
