# Employee Onboarding

Give a new hire a plan that turns "figure it out" into a clear path to productive,
sequenced so nothing critical is forgotten on day one.

## When to use

Use this skill when a new hire is joining and you need a structured first-day, first-week,
and first-month plan, or when onboarding is currently ad hoc and people ramp by accident.
Tailor it to the role — an engineer, a salesperson, and an ops hire need different ramps.

## How to build the plan

1. **Sort access by when it is needed.** Day-one essentials (accounts, hardware, building
   or system access, the core tools to do the job) versus what can wait a week.
   - List what must be requested before the start date so nothing blocks day one.
   - Note who owns each request; never make the new hire chase their own access.
2. **Schedule introductions with a purpose.** Manager and team first, then the cross-
   functional partners and the one or two go-to people for common questions.
   - Pair each intro with why it matters ("owns the handoff you depend on"), not just a
     name on a calendar.
3. **Sequence ramp tasks from observe to contribute.** Week one is reading, shadowing,
   and setup; week two starts small supervised work; by week four they own something real.
   - Make the first task small, finishable, and low-risk — an early win beats a heroic one.
4. **Set 30/60/90 milestones tied to outcomes.** 30 = oriented and doing supervised work;
   60 = owning routine work independently; 90 = fully ramped on the core responsibility.
   - Phrase each as an observable result the new hire and manager both agree on up front.
   - Schedule a check-in at each mark to confirm progress and adjust.
5. **Assign a buddy and a feedback loop.** A peer for the unwritten how-things-work
   questions, plus a regular manager 1:1 from week one so problems surface early.

## Output format

```
New hire: <role> · Start: <date> · Manager: <name> · Buddy: <name>
Before day 1 (owner): accounts · hardware · access requested
Day 1: setup · welcome · manager 1:1 · first small task
Week 1: key intros (with why) · core-tool ramp · shadowing
Month 1: first owned task · recurring 1:1s
30 / 60 / 90: <outcome> · <outcome> · <outcome>  (check-in at each)
```

Keep it to one page. A plan no one opens after day one is not a plan.
